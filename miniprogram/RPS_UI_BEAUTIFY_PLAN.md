# 猜拳大战 UI 全面美化计划

> 版本：v1.0 ｜ 日期：2026-07-27
> 范围：`packageCreate/pages/create/rps/` 下 5 个页面（主页 / 经典对战 / 闯关挑战 / 故事冒险 / 锦标赛）
> 原则：**只改 WXML / WXSS，不动 JS 游戏逻辑**（仅允许为样式挂载新增 class 绑定）

---

## 一、现状诊断

### 1.1 当前问题总览

| 维度 | 现状 | 问题 |
|---|---|---|
| 配色 | Material 默认色（#E91E63 深粉 / #FF9800 橙 / #4CAF50 绿） | 与全局亲子粉（#FF9AAB→#FF6B8A）脱节；"模板感"重 |
| 一致性 | 主页粉色、classic 粉色、challenge/tournament 橙色 | 同一模块内各页配色各自为政 |
| 氛围 | 白卡片 + 浅灰边框 + emoji | 没有"对战/擂台"的游戏临场感 |
| 出拳区 | 200rpx 白圆 + 灰边框 | 平淡，无角色感、无冲击力 |
| 按钮 | 扁平白卡片，仅 `:active scale(0.98)` | 无立体感、无按压反馈层次 |
| 动效 | shake / pulse / 单层 emoji 撒花 | 基础，缺少对撞、冲击波、屏幕震动等打击感 |
| 背景 | 单一线性渐变 | 空、无场景感 |
| 字体层级 | 标题 40-44rpx，正文 24-28rpx | 层级对比弱，重点不突出 |

### 1.2 各页面现状速览

- **rps/index（主页）**：粉紫渐变头 + 4 张白色模式卡 + 战绩列表。头部无装饰，卡片无主题色区分，战绩区简陋。
- **rps/classic（经典对战）**：核心玩法页。含模式选择 / 难度选择 / 人机对战 / 亲子双人 / 亲子随机 5 个阶段。比分板是白卡片，出拳圆盘无个性，结果徽章是浅色 pill。
- **rps/challenge（闯关挑战）**：橙色系，10 关进度展示，关卡节点样式简单。
- **rps/story（故事冒险）**：7 章剧情，章节卡片 + 对话区，文本呈现偏文档化。
- **rps/tournament（锦标赛）**：橙色系，对阵表（bracket）为白块堆叠，晋级路径不直观。

## 二、设计方向

### 2.1 主题概念：「猜拳竞技场」

明亮的卡通竞技场风——像 Switch 派对游戏：浅色糖果色场景 + 擂台元素 + 立体街机按钮 + 夸张的胜利反馈。兼顾 4 岁孩子的可爱感与对战的热血感。

**关键词**：圆润、立体、弹跳、聚光灯、糖果色、打击感。

### 2.2 设计 Token（全模块统一）

```css
/* ===== 主色板（与全局亲子粉衔接并提亮） ===== */
--rps-primary:      #FF6B8A;   /* 主粉：主按钮、标题强调 */
--rps-primary-deep: #E8527A;   /* 深粉：渐变末端、按压态 */
--rps-gold:         #FFB830;   /* 金色：胜利、奖杯、连胜 */
--rps-ink:          #3A2E4D;   /* 主文字：深紫灰（替代纯黑#333，更柔和） */
--rps-ink-light:    #8A7FA0;   /* 次要文字 */

/* ===== 三拳专属色（增强识别，全模块统一） ===== */
--rps-rock:     #7C8DB0;  /* 石头：岩蓝灰 */
--rps-scissors: #3EC6B8;  /* 剪刀：青碧 */
--rps-paper:    #FF9F43;  /* 布：暖橙 */

/* ===== 结果色 ===== */
--rps-win:  #4CAF6D;   /* 胜：青绿 */
--rps-lose: #FF5A5A;   /* 负：珊瑚红 */
--rps-draw: #FFB830;   /* 平：金 */

/* ===== 背景 ===== */
--rps-bg: linear-gradient(180deg, #FFF0F4 0%, #F3F0FF 55%, #EAF6FF 100%);
  /* 粉→紫→天蓝的明亮天空渐变，替代单一粉背景 */

/* ===== 卡片与阴影（立体糖果感） ===== */
--rps-card-bg:    #FFFFFF;
--rps-radius-lg:  32rpx;
--rps-radius-md:  24rpx;
--rps-shadow-1:   0 6rpx 20rpx rgba(58, 46, 77, 0.08);           /* 悬浮卡 */
--rps-shadow-2:   0 12rpx 32rpx rgba(58, 46, 77, 0.12);          /* 强调卡 */
--rps-border:     3rpx solid rgba(58, 46, 77, 0.06);             /* 柔边 */

/* ===== 立体按钮（街机感：顶面 + 底部厚度条） ===== */
--rps-btn-depth:  8rpx;   /* 按钮底部厚度，按压时压缩为 2rpx */

/* ===== 字号层级 ===== */
--rps-fs-hero:   64rpx;  /* 页面主标题 / 大比分 */
--rps-fs-title:  40rpx;  /* 区块标题 */
--rps-fs-body:   30rpx;  /* 正文 */
--rps-fs-aux:    24rpx;  /* 辅助说明 */
```

> 落地方式：微信 WXSS 支持 CSS 变量（基础库 2.x+），在各页 `.container` 或公共片段声明；不支持变量的场景直接写色值，以上表为准。

### 2.3 通用组件规范

**A. 立体按钮（全模块替换现有扁平按钮）**
- 结构：顶面（主色渐变）+ 底部 8rpx 深色厚度条（同色加深 15%）+ 整体圆角 28rpx。
- 按压：`transform: translateY(6rpx)` + 厚度条压缩为 2rpx，模拟街机按钮"按下去"。
- 主按钮粉、成功按钮绿、次要按钮白底灰边。

**B. 三拳出拳按钮（石头/剪刀/布）**
- 各自绑定专属色：石头岩蓝灰、剪刀青碧、布暖橙，顶面径向高光（`radial-gradient` 顶部 30% 白色 25% 透明）模拟立体感。
- 尺寸从 140rpx 加大到 **168rpx**（儿童触摸目标更大），圆角 40rpx 或正圆。
- 图标下方文字改为"徽章式"白底小 pill，与按钮颜色描边呼应。
- 增加 idle 呼吸浮动动画（上下 6rpx、3s 循环、三者相位差 0.4s）。

**C. 比分板**
- 从"白卡片"升级为"擂台记分牌"：深色（#3A2E4D）底板 + 两侧玩家色块 + 中央 VS 徽章（圆形金底描边）。
- 分数用 64rpx 粗体白色，加分时 `scoreBounce` 保留并叠加一次金色闪光扫过（`::after` 扫光动画）。
- 连胜时玩家名旁显示小火苗 🔥 角标。

**D. 对战出拳展示区**
- 双方圆盘改为"角色台座"：圆盘 + 底部椭圆阴影 + 所属方主题色光环（我方粉、对方青）。
- 占位 `?` 改为半透明拳头剪影样式（浅紫灰 #C9C2D9 + 虚线描边）。
- 胜方光环扩散脉冲（box-shadow 0 0 40rpx 金色），负方灰化 + 轻微下沉。

**E. 结果徽章 / 结算卡**
- 回合结果：从浅色 pill 升级为色块横幅——胜=金底"胜利!"，负=珊瑚红，平=灰蓝，配 0.4s 弹入（scale 0.6→1.05→1）。
- 整局结算卡：顶部奖杯区加"领奖台"三级台阶图形（纯 CSS 三个矩形），冠军站 C 位；卡片入场 fadeInUp + 奖杯 wobble 摇摆。

**F. 场景背景**
- 各页统一天空渐变（见 token `--rps-bg`）。
- 主页与对战页叠加氛围元素：2-3 朵缓慢漂移的白云（CSS 椭圆组合或 emoji ☁️ 低透明度）、顶部聚光灯光锥（半透明白色梯形渐变，从顶部两角向中央汇聚）。
- 注意：**所有 `position: fixed` 全屏层（撒花/特效/光锥）必须直接挂在页面根容器下**，不得嵌入带 transform 动画的父级（已知踩坑规则）。

## 三、分页面美化方案

### 3.1 rps/index 主页（P0）

1. **头部**：粉紫渐变头 → 改为天空渐变上的"竞技场门头"：
   - 标题"猜拳大战"改为 64rpx 粗体白字 + 金色描边感（text-shadow 多层），上方加 ✊✌️✋ 三拳小图标横排做"跳动"入场（依次 0.15s 延迟弹入）。
   - 背景加两束聚光灯光锥 + 漂浮星星（✨ 低透明度慢闪）。
   - 音效开关按钮改为圆形白底立体小按钮，与整体按钮规范一致。
2. **数据条 stats-bar**：白卡 → 深色记分牌风格（同比分板规范），三个数据项数值用金色，数字滚动入场（count-up 由 JS 已有数据直接渲染即可，仅做视觉强调，不改逻辑）。
3. **模式卡片**：4 张卡各自主题化，不再清一色白卡：
   - 经典对战=粉色、闯关挑战=金色、故事冒险=青碧、锦标赛=紫蓝（各 20% 透明度渐变底 + 2.5rpx 主题色描边 + 左侧 12rpx 主题色竖条）。
   - 图标位改为 96rpx 圆形主题色底托 + emoji 居中；右侧箭头 › 改为主题色圆底白箭头。
   - 卡片入场：依次 0.08s 间隔 fadeInUp。
4. **最近战绩**：结果"胜/负/平"改为小色块徽章（绿/红/金圆角 pill + 白字），列表卡化、行间留白加大。

### 3.2 rps/classic 经典对战（P0，核心）

1. **模式/难度选择阶段**：
   - 三个模式卡（亲子/随机/人机）横排改为大圆角竖卡，各配主题色图标底托；难度三档（简单/中等/困难）保留绿/橙/红语义但统一到 token 色板并做立体按钮化。
2. **比分板**：按通用规范 D 改造；亲子模式复用同一结构。
3. **倒计时**：数字加大至 160rpx，外圈加环形进度条（CSS conic 或旋转边框），每跳一次数字脉冲 + 圆环收缩。
4. **对战区**（重点打击感）：
   - 出拳动画从"原地 shake"升级为**对撞式**：双方拳头从左右两侧平移冲向中央（各 40% 屏宽，0.6s），撞击瞬间屏幕微震（根容器 0.3s 小幅度 translate，注意全屏 fixed 层不得挂在该容器内）、撞击点迸发白色冲击波环（scale 0→2.5 扩散淡出）+ 粒子星星 4-6 颗飞散。
   - 揭示结果后：胜方金环脉冲 + 轻微上跳，负方灰化下沉。
5. **出拳按钮**：按通用规范 B（三色立体街机按钮 + 呼吸浮动）。
6. **撒花**：单层 emoji 下落 → 双层彩带（前排大 🎊 快速、后排小 ✨ 慢速错相位）+ 顶部中央"彩带喷射"源点；**保持 confetti-container 挂在页面根级**。
7. **结算卡**：按通用规范 E（领奖台 + 奖杯摇摆 + 按钮立体化）。
8. **亲子随机模式**：大骰子按钮改为金色立体按钮，按下时骰子 🎲 快速旋转 0.6s。

### 3.3 rps/challenge 闯关挑战（P1）

1. **关卡进度**：10 关节点改为"冒险地图路径"——波浪曲线串联圆形关卡节点（已过=金色实心 + 皇冠、当前=粉色脉冲光圈、未解锁=灰色 + 🔒），替代当前平铺列表。
2. **关卡卡片**：当前关突出显示（放大 1.05 倍 + 主题色描边 + 阴影加深）。
3. **战斗界面**：复用 classic 美化后的比分板/出拳区/按钮规范，保证跨页一致。
4. **通关反馈**：过关时金色"过关!"横幅弹入 + 撒花；全部通关给奖杯结算卡。

### 3.4 rps/story 故事冒险（P1）

1. **章节选择**：章节卡片改为"卷轴/地图"风——左侧章节序号大数字徽章（金色圆底）+ 右侧标题与简介，已解锁/未解锁明暗区分，当前章呼吸光圈。
2. **剧情对话区**：改为对话气泡样式（圆角气泡 + 小三角尾巴 + 角色 emoji 头像在气泡旁），告别文档式段落。
3. **战斗段落**：进入对战时复用统一对战组件样式。
4. **章节完成**：印章式"已通关"红色圆章斜盖在章节卡右上角（rotate -12deg）。

### 3.5 rps/tournament 锦标赛（P1）

1. **对阵表（bracket）**：白块堆叠 → 真正的淘汰赛树：
   - 每轮一列，选手为圆角胶囊卡（名字 + 头像 emoji），胜者金色描边 + 连线（伪元素画横竖连接线）指向下一轮。
   - 当前进行中的对阵卡加脉冲光圈提示。
2. **冠军展示**：结算时"C 位领奖台"（同 classic 结算规范），冠军名字 64rpx 金色。
3. **操作按钮**：全部替换为立体按钮规范。

## 四、动效清单（新增/升级）

| 动效 | 用途 | 参数 |
|---|---|---|
| 对撞平移 | 双方出拳揭示前 | 0.6s ease-out，各平移 40% 屏宽 |
| 冲击波环 | 撞击瞬间 | 白色圆环 scale 0→2.5，0.5s 淡出 |
| 屏幕微震 | 撞击瞬间 | 根容器 translate ±8rpx，0.3s（fixed 层避开此容器） |
| 粒子飞散 | 撞击/胜利 | 4-6 颗 ✨ 随机方向 0.8s |
| 按钮呼吸 | 出拳按钮 idle | translateY ±6rpx，3s 循环，相位差 0.4s |
| 弹入 bounceIn | 结果横幅/卡片 | scale 0.6→1.05→1，0.4s |
| 奖杯 wobble | 结算卡奖杯 | rotate ±8deg，1.2s × 2 |
| 扫光 shine | 比分变化 | ::after 白色 30% 斜条 0.6s 扫过 |
| 云漂移 | 主页/对战页背景 | 60-90s 横移循环，透明度 0.5 |
| 彩带双层 | 胜利 | 前排 1.2s 快落 + 后排 2s 慢落 |

**性能红线**：
- 同屏动画元素 ≤ 12 个；阴影动画优先用 `transform`/`opacity`，避免动画中改 `box-shadow`/`filter`。
- 不使用 `backdrop-filter`；blur 仅限静态背景装饰。
- 所有循环动画在页面 `onHide` 时依赖 wx:if 销毁（WXML 结构已按阶段条件渲染，沿用即可）。

## 六、约束与风险

1. **不改逻辑**：仅 WXML 结构调整 class / 包裹装饰层，JS 的 phase、数据绑定、事件名一律不动。
2. **fixed 层规则**：撒花、冲击波、光锥等全屏 fixed 元素，必须直接放页面根容器，禁止嵌入带 transform 动画的祖先（2026-07-23 刷牙页踩坑）。
3. **兼容性**：CSS 变量需基础库 2.x+（项目已满足）；`gap`、伪元素、动画在目标机型已验证可用（现有代码已在用）。
4. **文件量**：5 个 wxss 各 500-650 行将重写为约 600-800 行；classic 因阶段最多最重，建议单独一个工作单元完成。
5. **回归测试**：美化后跑一遍经典三局两胜、闯关 1 关、故事 1 章、锦标赛 1 场的完整流程。
