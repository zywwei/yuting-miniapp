## 17:00 追加：本机也不显示的根因（doc(id) 直写 bug）+ 修复

- 现象：新图上传云存储成功，但本机也看不到预览。
- 根因：`brushing.js applyEditedPhoto`（画画编辑照片入口）用 `wx.cloud.database().collection('brushingRecords').doc(record.id).update()` 直写云端——**doc(客户端业务id) 与云数据库 _id 不匹配 → 找不到文档 → catch 静默失败 → 云端记录从未更新**。且漏更新 imagePath。之后 fetchBrushingRecords 的 mergeAndHeal 云端优先并回写本地缓存（cloud.js:1135-1180），把本地刚更新的 cloud:// 覆盖回脏路径 → 本机也裂图。
- 修复：applyEditedPhoto 改走 record 云函数（action:'update', id: record.id），updateRecord 有 doc(id)→where({id}) 兜底查找；同时补上 imagePath 字段。后端 sanitize 顺带过滤脏路径。语法验证通过。
- 排查确认：全项目无其他 `wx.cloud.database().collection(` 直写；brushing-timer.js 的 applyEditedPhoto 只改本地临时状态，无云端写入，无需改。
- **关键教训**：本项目云数据库 _id 为自动生成，客户端业务 id 存于字段 id，**禁止用 doc(客户端id) 直写数据库**，必须走 record 云函数（有 where({id}) 兜底）。

## 17:14 追加：https 临时链接丢图 bug + 完整修复

- 现象：本机上传成功但本机也不显示。
- 根因（更深一层）：fetchBrushingRecords 拉数据时云函数把 cloud:// 转成 https 临时链接 → mergeAndHeal 把 https 回写本地缓存。之后"添加照片"时 existingImages = [https 链接]，传给 updateBrushingRecord：
  - 16:53 加的 accessSync 检查把 https 当"本地文件不存在"跳过 → 原图从 images 丢失 → 云端 update 后原图没了
  - https 临时链接本身会过期（getTempFileURL 有时效）→ 缓存里的过期链接也显示不出来
- **本轮修复（3 处，语法已验证）**：
  1. `record/index.js resolveCloudFileIDs`：转换前保留原始 cloud:// 到新字段 `imageFileIDs`/`imagePathFileID`/`cloudFileIDRaw`，客户端显示用 https，编辑/更新时用原始 fileID 找回。

  3. `brushing.js applyEditedPhoto`：编辑时 images 里的 https 链接同样用 record.imageFileIDs[idx] 找回原始 cloud://，避免被后端 sanitize 过滤丢图。
- 设计要点：本地缓存存 https 临时链接（为跨账户显示），但更新时必须还原为 cloud:// 原始 fileID，否则后端 sanitize（只留 cloud://）会丢图。
