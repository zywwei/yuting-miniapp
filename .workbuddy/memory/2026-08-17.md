## 总积分/贴纸册显示 0、1 的根因修复（brushing-stats）

**根因**：`totalBrushPoints`、`toothDecorations` 两个单例存储**从未有业务代码写入**——计时器模式刷牙时积分/贴纸只写在每条记录里（`record.points`、`record.stickers`），统计页却读单例存储，导致总积分恒为 0、贴纸册只剩云端残留旧数据（1 条）。

**修改**（`brushing-stats.js`）：
1. `loadData` 中总积分改为从 records 实时汇总 `reduce((sum, r) => sum + (r.points || 0), 0)`，再与单例存储取较大值兼容云端旧数据
2. 新增 `buildDecorations(records)`：从记录收集含 stickers 的记录（date+timeOfDay 去重、按 createTime 倒序保留最新），再合并旧单例数据（同日同时段记录优先）

**验证**：Node 测试通过——同日同时段多条取最新；记录与旧单例去重记录优先；积分求和正确。

**备注**：打卡模式（brushing.js）保存的记录无 points/stickers 字段（`|| 0` 已兜底）；如后续要给打卡也加积分需在打卡保存处补逻辑。

## 打卡返回误报"未保存"修复（detail.js + checkin.js）

**根因**：goBack 用「表单里是否有非空值」判断是否有未保存内容，但表单**初始默认值本身非空**：
- `initFormData` 中 `field.type === 'time' && defaultToNow` 默认填入当前时间（"10:44"）
- counter 字段 `field.default || 0` 默认值可能非 0

打卡完成后虽重置表单，但默认时间/默认计数依然非空 → 返回时误判为"有未保存内容"弹暂存提示。

**修复**：改为「基线快照比较」方案：
1. 新增 `captureFormState()`：JSON 序列化 images/note/score/formData
2. onLoad 中（restoreDraft **之前**）记录 `this._baseline`
3. 打卡完成重置表单后更新 `_baseline`
4. goBack 改为 `captureFormState() !== _baseline` 判断

**语义**：初始/打卡后无差异 → 不提示；用户真实修改（改时间/加图/改分/留言）→ 提示；恢复暂存后内容与基线不同 → 提示（避免暂存内容静默丢失）。

**验证**：Node 测试 7 场景全部通过（初始/打卡后不提示，修改/加图/恢复暂存/改计数提示）。
