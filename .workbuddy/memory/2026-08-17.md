## 打卡返回误报"未保存"修复（detail.js + checkin.js）

**根因**：goBack 用「表单里是否有非空值」判断是否有未保存内容，但表单**初始默认值本身非空**：
- `initFormData` 中 `field.type === 'time' && defaultToNow` 默认填入当前时间（"10:44"）
- counter 字段 `field.default || 0` 默认值可能非 0

打卡完成后虽重置表单，但默认时间/默认计数依然非空 → 返回时误判为"有未保存内容"弹暂存提示。

**修复**：改为「基线快照比较」方案：
1. 新增 `captureFormState()`：JSON 序列化 images/note/score/formData
2. onLoad 中（restoreDraft **之前**）记录 `this._baseline`
3. 打卡完成重置表单后更新 `_baseline`
4. goBack 改为 `captureFormState() !== _baseline` 判断

**语义**：初始/打卡后无差异 → 不提示；用户真实修改（改时间/加图/改分/留言）→ 提示；恢复暂存后内容与基线不同 → 提示（避免暂存内容静默丢失）。

**验证**：Node 测试 7 场景全部通过（初始/打卡后不提示，修改/加图/恢复暂存/改计数提示）。

## 笔记模块 UI 颜色全部失效的根因修复（重要！）

**威哥反馈**：新版落地后档案卡"白色底也有背景色"、效果与设计不一致。

**根因**：微信小程序 WXSS **不支持 `:root` 选择器**！`:root` 里声明的 CSS 变量会被直接忽略（不报错），所有 `var(--xxx)` 引用全部失效 → 背景渲染为透明（露出下层渐变）、文字变默认色。这解释了：① 档案卡白底丢失露出头部渐变；② **旧版笔记页为什么"简陋像 demo"——颜色体系从来就没生效过**。

**修复**：
1. `index.wxss` 全面重写为**全硬编码**（禁 var()），顺带修复：
   - `.app-head` 去掉 `overflow: hidden`（否则多孩子时 child-switcher 下拉面板被裁剪）
   - `.cover-shade` 的 `inset: 0` → top/right/bottom/left 显式（兼容性）
   - cover 300→280rpx、cd 84→76rpx（贴近设计稿比例）、档案卡 margin/头部 padding 微调
2. `add.wxss`(101处) / `detail.wxss`(57处) / `drafts.wxss`(29处) 用 Node 脚本批量替换 var() 为硬编码 + 删除 :root 块，共 187 处

**验证**：4 个 wxss var 残留 0、:root 仅注释、花括号平衡；首页 122 类名全覆盖；JS 语法 OK。

**约定（写进项目规范）**：本项目 WXSS 一律硬编码颜色，禁止用 :root + var()。若真要用 CSS 变量需放 `page {}` 且低版本基础库仍可能失效。
